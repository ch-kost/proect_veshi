# Система учета истории владения предметами

Консольное приложение хранит предметы, владельцев и все периоды владения.
Версия ПР5 добавляет к объектной модели ПР3 веб-интерфейс на Django 5.2.
Веб-страницы читают прежние JSON-файлы и показывают предметы, владельцев
и периоды владения. Консольное меню остается доступным.

## Веб-версия ПР5

Django-проект `ownership_site` подключает четыре приложения: `homepage`,
`catalogue`, `owners` и `history`. Их `urls.py` содержат именованные маршруты
и пространства имен. Представления возвращают `HttpResponse`, используя
общий HTML-каркас `page()`, CSS и Bootstrap 5.3.3.

| URL | Страница |
| --- | --- |
| `/` | Главная и статистика |
| `/items/` | Список предметов; поиск `?q=фото`, сортировка `?sort=desc` |
| `/items/<id>/` | Предмет, текущий владелец и история |
| `/owners/` | Владельцы |
| `/owners/<id>/` | Владелец и его периоды владения |
| `/history/` | Все периоды владения и их состояние |
| `/history/<id>/` | Период с ссылками на предмет и владельца |

Несуществующие идентификаторы возвращают HTTP 404. Собственный обработчик
неизвестных адресов работает при `DJANGO_DEBUG=0`. Ошибка чтения JSON
выводит понятную страницу HTTP 503. GET-запросы не изменяют данные.

## Возможности

- просмотр, поиск, добавление и сортировка предметов;
- просмотр владельцев и полной истории владения;
- передача предмета существующему или новому владельцу;
- отмена последней передачи;
- расчет длительности завершенных периодов;
- статистика и автоматическое сохранение в JSON.

Дата вводится как `ДД.ММ.ГГГГ`, например `14.09.2026`. Также принимается
формат `ГГГГ-ММ-ДД`, который используется в JSON-файлах.

## Объектная модель

- `Entity` — базовый класс сущностей с положительным идентификатором;
- `Item(Entity)` — предмет, содержащий историю и операции передачи;
- `Owner(Entity)` — владелец предметов;
- `OwnershipPeriod(Entity)` — связь предмета и владельца на интервале дат.

`Item` и `Owner` демонстрируют наследование от общей сущности. Их разные
реализации `__str__()` полиморфно используются при выводе. Закрытие и повторное
открытие периода выполняются методами, поэтому некорректное состояние нельзя
создать прямым изменением даты. Объект `OwnershipPeriod` связывает конкретные
объекты `Item` и `Owner`, что демонстрирует композицию и взаимодействие.

## Структура

```text
proekt/
├── main.py                  # меню и пользовательские сценарии
├── models/                  # Entity, Item, Owner, OwnershipPeriod

├── storage.py               # преобразование объектов в JSON и обратно
```

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Для веб-версии после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте <http://127.0.0.1:8000/>. `migrate` создает только служебные
таблицы Django; предметная область пока не использует ORM. `db.sqlite3`
исключена из Git. Формы и авторизация для предметной области будут добавлены
в следующих практических работах. Локальные настройки и открытый учебный
SECRET_KEY не предназначены для публикации сервера в интернете.

Чтобы проверить собственную страницу 404 из PowerShell:

```powershell
$env:DJANGO_DEBUG = '0'
.\.venv\Scripts\python.exe manage.py runserver
```

После проверки остановите сервер (`Ctrl+C`) и выполните
`Remove-Item Env:DJANGO_DEBUG`, чтобы вернуть режим разработки.

## Тестирование и качество кода

```powershell
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 . --exclude=.venv
```

Тесты проверяют создание и взаимодействие объектов, наследование,
полиморфный вывод, передачу и отмену, обработку ошибок, функции коллекций и
полный цикл сохранения/загрузки JSON с восстановлением ссылок между объектами.
Веб-тесты используют временные JSON, проверяют маршруты, отображение данных,
ошибки 404/503, запрет POST, экранирование HTML и отсутствие изменений после
просмотра страниц. На этапе ПР5 проходят 42 теста. Конфигурация `.flake8`
исключает виртуальное окружение из проверки.

Структура веб-части: `manage.py`, `ownership_site/`, `homepage/`, `catalogue/`,
`owners/`, `history/`, `web_data.py`. Старые `models/`, `services.py`,
`storage.py`, `utils.py`, `main.py`, `data/` и их тесты продолжают работать.
